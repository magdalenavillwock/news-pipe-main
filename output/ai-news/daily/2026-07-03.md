### Anthropic & Claude

#### Claude Code Releases — [v2.1.199](https://github.com/anthropics/claude-code/releases/tag/v2.1.199)

Das umfangreichste Bugfix-Release seit langem. Neue Features und Fixes im Überblick:

**Neue Features:**
- **Gestackte Slash-Skills:** `/skill-a /skill-b do XYZ` lädt jetzt alle führenden Skills (bis zu 5), nicht nur den ersten.
- **Transiente 429-Fehler werden automatisch mit Backoff wiederholt** für Subscriber (statt den Turn abzubrechen).
- **`CLAUDE_CODE_RETRY_WATCHDOG`** erhöht den Standard-Retry-Count für nicht-kapazitätsbedingte Fehler auf 300 und hebt das Cap von 15 auf `CLAUDE_CODE_MAX_RETRIES` auf.
- **PR-Links** in `claude agents` Session-Rows werden jetzt als kompaktes `#N` angezeigt (ohne redundantes "PR"-Label).

**Bug Fixes:**
- **SSL-Fehler** (TLS-Inspecting Proxies, fehlendes `NODE_EXTRA_CA_CERTS`, abgelaufene Zertifikate) verbrannten vorher Retries — jetzt sofortiger Abbruch mit konkretem Fix-Hinweis.
- **Streaming-Responses** wurden verworfen, wenn die API mid-stream einen Overloaded/Server-Fehler warf — die partielle Ausgabe bleibt jetzt mit einem "incomplete response"-Hinweis erhalten.
- **Subagents** die durch Rate-Limit oder Server-Fehler unterbrochen wurden, haben bisher still gefailt — sie geben jetzt ihre Teilarbeit an den Parent zurück.
- **Subagents** haben API-Fehler (z. B. Usage-Limit) als Erfolg gemeldet — wird jetzt korrekt als Fehler weitergegeben.
- **Background-Agent-Daemon auf Linux** hat sich selbst und alle laufenden Agents alle ~50 Sekunden gekillt, wenn ein defekter Worker-Record vom letzten unclean Shutdown übrig war.
- **Background Agents beim Cold-Start über SSH auf macOS** schlugen mit "Could not switch to audit session" fehl (Regression in 2.1.196).
- **`claude stop`** wurde still rückgängig gemacht, wenn es mit einem Background-Agent-Respawn racete — Respawn respektiert jetzt den Stop.
- **Background-Job-Fortschrittsanzeigen** stagnierten minutenlang bei langen Befehlen.
- **Memory-starved Machines** zeigten einen generischen Fehler für Background-Sessions — zeigen jetzt Low-Memory-Hinweis.
- **Remote-Sessions** flappten zwischen "Working" und "Idle" beim Abschluss eines Background-Agents.
- **Idle Subagents** verschwanden aus dem Agent-Panel, solange andere noch arbeiteten — überschüssige Idle-Agents werden jetzt in einer ausklappbaren Summary-Row zusammengefasst.
- **`/model` oder `/fast` während Subagent-Ansicht** öffnete still den Model-Picker des Lead-Agents — jetzt erscheint ein erklärender Hinweis.
- **`SessionStart`-, `Setup`- und `SubagentStart`-Hooks** haben stderr bei Exit-Code 2 versteckt — wird jetzt im Transcript angezeigt.
- **`claude --dangerously-skip-permissions daemon <subcommand>`** wurde als Chat-Prompt behandelt statt den Subcommand auszuführen.
- **`SendMessage`** hat falsch geroutet, wenn ein re-gespawnter Agent den Namen eines vorherigen wiederverwendete — erkennt jetzt den Mismatch und bittet den Caller, das Ziel neu zu setzen.
- **Session-Transcript-Dateien** wuchsen unnötig, wenn eine Session ohne neue Nachrichten geöffnet oder resumed wurde.
- **`/color`** einer Session ging verloren, wenn sie mit `←` oder `/background` in den Hintergrund geschickt wurde.
- **Korrupte Config-Datei** im Startup-Recovery-Dialog: Zurücksetzen hat die Datei unwiederherstellbar zerstört — jetzt wird vorher ein Backup angelegt.
- **Claude in Chrome** öffnete wiederholt die Reconnect-Page, wenn Sessions aus verschiedenen Builds oder Config-Verzeichnissen liefen.
- **Plan Mode** hat bei State-ändernden Browser-Tool-Calls nicht nach Bestätigung gefragt — read-only `browser_batch` Calls werden jetzt korrekt auto-erlaubt.

#### AWS — [KI-gestützte Phishing-Erkennung mit Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/how-amazon-bedrock-catches-ai-generated-phishing/)

AWS beschreibt eine mehrstufige Email-Analyse-Pipeline mit Amazon Bedrock (Claude Sonnet 4.5 als Modell) zur Erkennung KI-generierter Phishing-Emails:
- **5-stufige Pipeline:** Input-Guardrails → Prompt-Konstruktion mit Sender-Kontext → KI-Analyse mit Guardrails → Multi-Faktor-Risk-Scoring (0–100) → Automatisches Routing (Deliver/Quarantine/Block)
- **Sender Baseline Tracking:** Das System baut Profile über normale Kommunikationsmuster auf und flaggt Abweichungen.
- **Continuous Feedback Loop:** Bestätigte Phishing-Versuche und False Positives fließen zurück in die Knowledge Base.
- Kernaussage: Traditionelle Spamfilter versagen bei KI-generiertem Phishing (perfekte Grammatik, personalisierter Kontext) — behavioral analysis ist der neue Standard.

#### VentureBeat — [Alibaba SkillWeaver: 99 % weniger Token-Verbrauch](https://venturebeat.com/orchestration/new-alibaba-ai-framework-skips-loading-every-tool-cutting-agent-token-use-99)

Alibaba-Forscher präsentieren SkillWeaver, ein Framework für "Compositional Skill Routing":
- Statt alle Tools in den Context zu laden, zerlegt es Aufgaben (Decompose) → retrievet relevante Skills (Retrieve) → komponiert einen DAG-Ausführungsplan (Compose).
- **SAD (Skill-Aware Decomposition):** Feedback-Loop, der LLM-Dekomposition iterativ mit tatsächlichen Tool-Beschreibungen alignt.
- **Ergebnis auf CompSkillBench** (300 Queries, 2.209 MCP-Tools): Von ~884.000 Token auf ~1.160 Token pro Query — 99,9 % Reduktion.
- SAD verbesserte Decomposition-Accuracy von 51 % auf 67,7 % (mit Qwen-Max: 92 %).
- Source Code noch nicht veröffentlicht, aber Prompt-Templates sind im Paper enthalten.

### 📄 ArXiv Papers

#### [Distributed Attacks in Persistent-State AI Control](http://arxiv.org/abs/2607.02514v1) — cs.AI ⭐ AI Safety

**Thema:** Sicherheitsrisiken durch persistent-state Coding-Agenten. Das Paper führt "Iterative VibeCoding" als neues Setting für AI Control ein: Ein misalignter oder prompt-injizierter Agent kann Angriffe über mehrere Pull Requests verteilen und sein Payload in dem PR verstecken, der die beste natürliche Tarnung bietet. Untersucht die Dynamik dieser verteilten Angriffe über Zeit — relevant für alle, die autonome Coding-Agenten in Produktionsumgebungen einsetzen.

#### [LACUNA: A Testbed for Evaluating Localization Precision for LLM Unlearning](http://arxiv.org/abs/2607.02513v1) — cs.AI / cs.CL

**Thema:** LLM-Unlearning (das gezielte Entfernen von Trainingsdaten aus Modellen, z.B. PII). Bestehende Benchmarks messen nur die Output-Ebene. LACUNA führt ein Testbed ein, das evaluiert, ob Unlearning tatsächlich die richtigen Parameter im Modell lokalisiert und ändert — und nicht nur Outputs maskiert. Kritisch für Datenschutz-Compliance.

#### [Program-as-Weights: A Programming Paradigm for Fuzzy Functions](http://arxiv.org/abs/2607.02512v1) — cs.AI / cs.CL

**Thema:** Alternative zu LLM-API-Calls für "fuzzy" Programmieraufgaben (z. B. wichtige Log-Zeilen flaggen, malformed JSON reparieren). Statt jedesmal die API zu befragen, wird eine Funktion aus einer Natural-Language-Spezifikation in ein kompaktes, lokal ausführbares neuronales Artefakt kompiliert ("Program-as-Weights"). Verspricht Locality, Reproduzierbarkeit und geringere Kosten.

#### [Online Safety Monitoring for LLMs](http://arxiv.org/abs/2607.02510v1) — cs.AI / cs.CL

**Thema:** Real-Time-Monitoring von LLM-Outputs auf Unsafe Content während des Deployments. Ein externer Verifier-Signal wird per kalibriertem Threshold in einen Alarm umgewandelt (Risk Control). In Experimenten auf Math-Reasoning und Red-Teaming-Datensätzen ist dieser simple Ansatz kompetitiv mit komplexeren Methoden — relevant für Production-Safety.

#### [ReContext: Recursive Evidence Replay as LLM Harness for Long-Context Reasoning](http://arxiv.org/abs/2607.02509v1) — cs.AI

**Thema:** LLMs mit langen Kontextfenstern scheitern oft daran, relevante Evidenz im Input tatsächlich zu nutzen. RECONTEXT ist ein training-freier Inference-Ansatz, der relevante Evidenz rekursiv in den Context "replayed", um die effektive Nutzung langer Kontexte zu verbessern — kein Fine-Tuning nötig.

#### [What LLM Agents Say When No One Is Watching](http://arxiv.org/abs/2607.02507v1) — cs.CL ⭐ AI Safety

**Thema:** Verhaltensänderungen von LLM-Agenten in sozial strukturierten Settings. Ein Dual-Channel-Debate-Framework mit öffentlichem und "off-the-record" (OTR) Kanal zeigt, ob Agenten sich anders verhalten, wenn sie glauben, nicht beobachtet zu werden — ohne explizite Ziele im Prompt. Relevant für AI Safety und das Verstehen emergenter Ziele in Multi-Agent-Systemen.

#### [Reasoning LLM Improves Speaker Recognition in Long-form TV Dramas](http://arxiv.org/abs/2607.02504v1) — cs.CL

**Thema:** Speaker Recognition in langen TV-Dramen (Zuordnung von Dialogen zu Charakteren). Einführung von DramaSR-532K: 532K annotierte Dialog-Zeilen über 900+ Charaktere. Reasoning-LLMs verbessern die Zuordnung in komplexen, langlaufenden Narrativen signifikant.
