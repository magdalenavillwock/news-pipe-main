### Claude Code Releases

**v2.1.259** ([Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.259))

Dieses Release ist außergewöhnlich umfangreich. Vollständige Auflistung aller Änderungen:

**Neue Features:**
- **`managedMcpServers`-Setting**: Organisationen können HTTP/SSE-MCP-Server zentral für alle Nutzer bereitstellen (gleiche Syntax wie `.mcp.json`). Einträge mit lokalem Kommando werden übersprungen.
- **`--permission-prompts none`**: Für unbeaufsichtigte, headless Umgebungen — alles, was normalerweise einen Prompt auslösen würde, wird automatisch abgelehnt, ohne den Auto-Modus zu deaktivieren.
- **GitLab-Integration**: `glab mr create/merge/close/reopen/note/update` werden erkannt; Merge Requests erscheinen als `MR !N` in der zusammengeklappten Tool-Zusammenfassung und aktualisieren den Footer-Badge.
- **`claude plugin validate --json`**: Maschinenlesbarer Validierungsreport für Plugins.
- **[VSCode] Session-Filter**: Neue "Active"-Schnellfilterung und Status-Filtermenü (Needs input, Working, Completed) in der Session-Sidebar.

**Bugfixes (kritisch/wichtig):**
- **Konkurrierende Sessions**: Gleichzeitige Sessions haben sich gegenseitig `~/.claude.json`-Änderungen überschrieben — Workspace Trust wurde zurückgesetzt, MCP-/Projektstatus ging verloren. Behoben.
- **Bash-Sicherheitslücken bei Deny-Regeln**: Dateien als Options-Werte übergeben (`--ignore-revs-file=.env`, `-f.env`, `@file`), `git diff`/`git grep`-Operanden oder `cd DIR && cat FILE`-Verbindungen wurden von Read()-Deny-Regeln nicht abgedeckt. `grep -r`/`cp -r` über Verzeichnisse mit abgelehnten Dateien fragen jetzt nach.
- **Thinking-Rejection-Loop**: Gespräche, deren Thinking einmal abgelehnt wurde, wurden bei jedem weiteren Turn erneut abgelehnt.
- **Prompt-Cache-Invalidierung**: Bei OAuth-Token-Refresh in Sessions ohne Telemetrie wurde der Cache unnötig invalidiert.
- **Fullscreen-Bug**: Langer Turn mit hunderten von Tool-Calls führte zu leerem Gesprächsbereich im Fullscreen-Modus.
- **Auto-Mode/Modell-Konflikt**: Auto-Mode startete einen Turn auf einem nicht unterstützten Modell, wenn das Frontmatter `model:` eines Commands/Skills ein anderes Modell benannte. Jetzt wird das Session-Modell beibehalten.
- **`CLAUDE_CODE_MAX_CONTEXT_TOKENS`** wurde für Vertex-Style-Modell-IDs (mit `@YYYYMMDD`-Suffix) ignoriert.
- **Shell-Ausgabe-Vorschau**: Neueste Zeilen einer laufenden Shell-Ausgabe wurden versteckt, wenn eine frühere Zeile umbrach.
- **GitHub-App-Check**: Beim Start jeder Session wurde ein Background-Check für claude.ai-Nutzer ausgeführt. Ergebnis wird jetzt gecacht.
- **`--resume`/`--continue`**: Fehler, wenn eine gespeicherte Session einen Anhang ohne Payload enthielt.
- **Frontmatter `model:`**: Wurde in interaktiven Sessions für Custom Commands und Skills ignoriert.
- **Artifact-Publishing**: Schlug einmalig mit "unexpected parameter `note`"-Fehler fehl, wenn aus einer älteren Version fortgesetzt wurde.
- **`forceRemoteSettingsRefresh`**: Wurde beim Start ignoriert, wenn ein Policy Helper via MDM bereits gelaufen war.
- **Worktree-Isolation**: Ablehnung bei hook-erstellten Worktrees auf Maschinen, wo `git rev-parse` mit unbekannter Fehlermeldung fehlschlägt.
- **OpenTelemetry**: Cloud-Sessions hatten fehlende `user.email`, `organization.id` und `user.account_uuid`-Attribute.
- **MCP-Server-Fehlerbehandlung**: Server, die beim Tool-Listing beim Start trennen, wurden als verbunden (ohne Tools) angezeigt statt den Fehler zu melden.
- **File-Edit-Permission-Dialog**: Geänderte Zeilen wurden manchmal abgeschnitten ohne Hinweis.
- **Repository-Erkennung**: Bekannte Repo-Identität wurde nach transientem git-Probe-Fehler vergessen.
- **Managed Settings Parsing-Fehler**: Claude Code startete bisher stillschweigend mit nicht-durchgesetzten Settings, wenn die Konfigurationsdatei nicht geparst werden konnte. Jetzt: Start wird verweigert mit Nennung der fehlerhaften Quelle.
- **Stop-Button**: Stop stoppte Background-Agents/Workflows in Remote-Control-Sessions nicht wirklich.
- **Workflow-Resume-Race-Condition**: Beim Resumieren eines Workflows während der vorherige Stopp-Vorgang noch lief, konnten doppelte Agent-Kopien entstehen.
- **Marketplace-URLs**: GitHub-URLs mit trailing Slash oder `?`/`#` erzeugten unbrauchbare `.git`-Clone-URLs.
- **Stop-Hooks**: Blockierende Stop-Hooks ließen das Modell-Reasoning des nachfolgenden Turns verlieren.
- **Remote-Sessions**: Brauchten 60 Sekunden zum Start eines Turns, nachdem eine browser-gehostete MCP-Server-Seite geschlossen wurde.
- **Worktree-Sessions**: Verweigerten häufig verwendete Bash-Schleifen, xargs-Pipelines und Wrapper-Kommandos.

**Verbesserungen:**
- Terminal-Resize und First-Render deutlich schneller bei langen Antworten durch Text-Measurement-Reuse.
- `/workflows`-Agent-Detail: JSON-Ergebnisse werden pretty-printed mit Syntax-Farben; lange Ergebnisse faltbar.
- Headless/SDK-Sessionstart: Erster Turn beginnt bis zu 50 ms früher.
- `/install-github-app` erklärt jetzt explizit, dass es nur für GitHub gilt, und verweist bei GitLab auf die CI/CD-Docs.
- Nested Background-Subagent-Ergebnisse werden im Parent-Transcript gespeichert für korrekte Resume-Funktionalität.
- **`allowedMcpServers`** regelt jetzt nur noch nutzerhinzugefügte Server (nicht mehr managed-mcp.json-Einträge). Nutzt `deniedMcpServers`, um managed-Server auszuschließen.
- Remote/scheduled Sessions tun nach Genehmigung eines Connector-Tool-Permission-Prompts jetzt wieder etwas.

### Meta

**Organizational Second Brain** ([Meta Engineering](https://engineering.fb.com/2026/09/02/ml-applications/organizational-second-brain-ai-learns-from-experts/))

Meta hat ein System vorgestellt, das institutionelles Expertenwissen in KI-Agenten überführt, ohne Modell-Retraining. Die Architektur:

- **Wissenssystem**: 200+ strukturierte Dateien mit Positionen, Taxonomien, Routing-Indizes und Gateway-Regeln — ein "Zweites Gehirn" der Organisation.
- **Recipes**: Komposierbare, imperative Prozeduren, die Reasoning-Abläufe beschreiben. Wissen und Prozedur sind strikt getrennt.
- **Self-Improvement-Flywheel**: Expertenkorrektur → Diagnose (Wissenslücke vs. Prozedur-Fehler) → automatische Minimal-Edits via Multi-Agent-Compiler → Validierung (Replay + Regression) → Human-Review → Landing. Jede Korrektur wird dauerhaft in die Regressionssuite aufgenommen.
- Ergebnisse nach 6 Wochen: Assessment-Zeit von Tagen auf Minuten reduziert, zero Regressionen, Domänen-SMEs nutzen ihre Zeit für wirklich ambivalente Fälle.

**Meta Muse Voice Transcribe** ([VentureBeat](https://venturebeat.com/technology/meta-prices-muse-voice-transcribe-at-0-18-an-hour-with-real-time-diarization-for-20-speakers-a-steal-for-enterprises))

- Real-Time-Streaming-STT mit eingebautem Speaker-Diarization für 20+ Sprecher.
- Preis: $0,18/Stunde (all-inclusive, kein Add-on für Diarization).
- 80ms-Chunks, adaptiver Delay via RL, 70+ Sprachen.
- Platz 1 auf Artificial Analysis Streaming STT Benchmark (Stand 1. September).
- Diarization Error Rate: 17,5 % (besser als Konkurrenz im Vergleich-Chart).

## 📄 ArXiv Papers

- **Discriminative World Models for Web Agents** ([Link](http://arxiv.org/abs/2609.02885v1)) — Web-Agenten nutzen normalerweise World Models durch Next-State-Prediction. Dieser Ansatz ist falsch ausgerichtet: Die generierten States müssen für den Ranker diskriminativ sein. Das Paper schlägt eine neue Trainings-Methode vor, die auf das Ranking-Ziel ausgerichtet ist.

- **TRACE: Transparent Reasoning Architecture for Credible Execution** ([Link](http://arxiv.org/abs/2609.02861v1)) — Framework für autonome Roboter mit 4-stufigem, auditierbarem Entscheidungs-Layer (Semantic Perception, Evidence-Gathering, Causal Reasoning, Action). Jede Entscheidung ist auf Sensordaten zurückverfolgbar.

- **Post-Training für Gold-Medal-Performance in Coding Competitions** ([Link](http://arxiv.org/abs/2609.02849v1)) — 22.000 kuratierte Probleme, SFT + RL für Nemotron-3-Nano-CC (30B) und SFT für Nemotron-3-Ultra-CC (550B). Erreicht Gold-Medaillen-Niveau bei IOI/ICPC.

- **User Feedback als einzigartiges LLM-Lern-Signal** ([Link](http://arxiv.org/abs/2609.02859v1)) — User-Feedback aus natürlichen Interaktionen ist entgegen bisherigen Studien ein hochwertiges Lern-Signal. Bisherige "Ineffektivität" entstand durch systematischen Bias in Evaluations-Paradigmen.

- **Dutch Books for Language Models** ([Link](http://arxiv.org/abs/2609.02797v1)) — Untersucht, ob LLM-Wahrscheinlichkeits-Prognosen kohärent sind (de Finetti-Theorem). Ergebnis: LLMs sind anfällig für Dutch Books, d.h. ihre Forecasts sind inkohärent.

- **EarlyEval: Günstigere Agent-Evaluation durch Early Outcome Prediction** ([Link](http://arxiv.org/abs/2609.02783v1)) — Frontier-Model-Evaluation kostet hunderte bis tausende Dollar pro Benchmark-Lauf. EarlyEval sagt das Endergebnis frühzeitig voraus und stoppt den Run wenn möglich früh.

- **LLMs für Telecom Root Cause Analysis** ([Link](http://arxiv.org/abs/2609.02805v1)) — Strukturiertes Reasoning-Framework für 5G/6G-Netzwerkdiagnose, das Halluzinationen reduziert und Evidenz-Grounding sicherstellt.

- **DiscoSign: Discourse-Aware Sign Language Translation** ([Link](http://arxiv.org/abs/2609.02796v1)) — LLM-basiertes Framework für Text-zu-Gebärdensprache-Übersetzung mit Berücksichtigung von räumlicher Koreferenz, Temporalität und Topic-Tracking.
