### AWS AI Blog

#### Best Practices: Amazon Bedrock Guardrails für Code-Generierung

Ausführlicher Artikel über häufige Throttling-Probleme bei naiver Guardrail-Konfiguration:
- **Problem:** Standard-Streaming-Intervall (50 Zeichen) × 3 Safeguards × 15 gleichzeitige Dev-Sessions = 1.500 API-Calls/Sekunde → ThrottlingException
- **Pattern 1 – Pre-Commit Hook:** Guardrails nur an Trust-Boundaries auslösen (User Input, Final Artifact, File Commit) — nicht bei jedem Streaming-Chunk
- **Pattern 2:** Streaming-Intervall auf 1.000 Zeichen erhöhen → 20× weniger API-Calls
- **Pattern 3:** Decoupled `ApplyGuardrail` API nutzen — nur neuen User-Input evaluieren, nicht jedes Mal System-Prompt mitschicken
- **Pattern 4:** Batching auf 1.000-Zeichen-Grenzen (Text-Unit-Granularität)
- **Pattern 5:** Risk-based Evaluation — IAM-Code vollständig scannen, UI-Komponenten erst beim Commit

→ [AWS ML Blog](https://aws.amazon.com/blogs/machine-learning/best-practices-for-applying-amazon-bedrock-guardrails-to-code-generation-workflows/)

#### Evaluating AI Agents: Strands + AgentCore (Motorway Case Study)

Motorway (UK Online-Automarktplatz) und AWS reduzierten falsche Suchergebnisse von 1:8 auf 1:50 mit einer strukturierten Evaluierungspipeline:

- **3-Layer-Framework:** Tool Usage (>95 %), Reasoning (>85 %), Output Quality (>90 %)
- **pass^k Metrik:** Statt pass@k (einmal erfolgreich) wird pass^k (k-mal hintereinander) gemessen — ein Agent mit 75 % Einzelerfolg hat nur 42 % pass^3
- **Shadow Mode:** 4 Stunden Live-Traffic im Parallel-Betrieb vor Rollout
- **Produktionsresultat:** Tool-Accuracy 87→98 %, Multi-Turn Context 71→94 %, Incidents 12→2/Monat

→ [AWS ML Blog](https://aws.amazon.com/blogs/machine-learning/evaluating-ai-agents-a-production-blueprint-with-strands-and-agentcore/)

#### AgentCore Optimization: Silent Failures erkennen

Amazon Bedrock AgentCore Insights analysiert Agent-Sessions und findet Fehler, die keine Error-Signale erzeugen:
- **11 Fehlerkategorien:** Halluzination, Incorrect Actions, Orchestration Errors u.a.
- **Failure Clustering:** Ähnliche Fehlermuster über hunderte Sessions zusammengefasst
- **User Intent Analysis:** Zeigt tatsächliche Nutzungsverteilung (oft überraschend anders als geplant)
- **Beispiel:** Market Trends Agent halluzinierte Finanzdaten ohne Tool-Aufruf — Session abgeschlossen, kein Error, nur durch Insights entdeckt
