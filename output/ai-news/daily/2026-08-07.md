### Claude Code Releases

**[v2.1.224](https://github.com/anthropics/claude-code/releases/tag/v2.1.224)**

Eines der umfangreichsten Releases seit langem. Im Detail:

**Neue Features:**
- **Self-Hosted Environments**: `claude self-hosted-runner` verwandelt eigene Maschinen oder Container in Ausführungsumgebungen für Claude Code Web-, Mobile- und Desktop-Sessions (Team- und Enterprise-Plan)
- **Archive Plugin Source**: Plugins lassen sich nun aus einem ZIP via HTTPS installieren, ohne Git oder npm — mit optionalem SHA-256-Pinning für Verifikation
- **Cancel-and-Confirm bei Paste-Änderungen**: Neuer Abbruch-und-Bestätigungs-Schritt, wenn das Entfernen eines nicht verfügbaren Pastes den Befehlstext verändert
- **`ANTHROPIC_BEDROCK_REGION_PREFIX`**: Neue Umgebungsvariable für Bedrock, um ein spezifisches Cross-Region-Inference-Profil gegenüber dem aus `AWS_REGION` abgeleiteten zu bevorzugen
- **`crossSessionInbound` und `dialogExpiry` Settings**: Cross-Session-Nachrichten an Sessions mit umgangenen Berechtigungen werden zur Genehmigung zurückgehalten; Nachrichten an andere Sessions werden automatisch zugestellt
- **Erweiterte Sandbox Credential-Masking**: `extract`/`onExtractNoMatch` für strukturierte Env-Werte, `decode: "jwt"` mit `maskClaims` für JWT-aware Masking, `awsPairs`/`sigv4` für AWS SigV4-Re-Signing (erfordert `network.tlsTerminate`)
- **Cross-Session `SendMessage`**: Claude Code-Sessions können sich nun gegenseitig Nachrichten schicken (macOS und Linux), `ListAgents` zur Entdeckung anderer Sessions

**Bug-Fixes:**
- Lange (>200 Zeichen) Projektpfade lösten fälschlicherweise in das Session-Verzeichnis eines anderen Projekts auf — behoben
- `SendMessage` meldete "Message sent" auch bei fehlgeschlagener Zustellung — jetzt korrekte Fehlermeldung
- Sandbox-Filesystem-Deny-Einträge mit Trailing Slash (z.B. `denyRead: "~/.aws/"`) konnten auf Linux und macOS umgangen werden — behoben
- Sandbox-Verletzungsdetails erschienen nie in Bash-Tool-Ergebnissen — Claude sieht jetzt welcher Datei-/Netzwerkzugriff verweigert wurde und warum
- MCP-Tools, die mid-turn verbinden, wurden ohne Namensankündigung verzögert — behoben
- Plugin-Installationseinträge wurden bei Mehrfachinstallation in verschiedenen Projekten beschädigt — behoben
- Paste-Content-Wiederherstellung konnte falsche Daten anhängen oder Text verlieren — behoben
- Copy-on-Select auf Wayland erreichte manchmal nicht die Zwischenablage (Race-Condition) — behoben
- Feedback-Survey-Transcript-Share schlug bei langen Sessions still fehl — jetzt Fehlermeldung
- Remote Control Auto-Start schlug intermittierend mit "Remote credentials fetch failed" fehl — behoben
- Remote Control und SDK-Clients zeigten leere "(no content)"-Nachrichten nach `/clear` — behoben
- Session-Neuanlage nach Ablauf uploadete vorherige lokale Konversationshistorie — behoben

**Verbesserungen:**
- Fullscreen-Modus behält jetzt die vollständige Pre-Compaction-History im Scrollback über mehrere Compactions hinweg
- Remote Control: Angehängte Web- und Mobile-Clients sehen jetzt Compaction-Fortschritt und Post-Compaction-Grenze; `/clear` propagiert zu allen Clients
- Remote Control: Verbindungsfehler zeigen jetzt einen persistenten Fehlerindikator mit Details und Reconnect-Shortcut
- **200-Subagent-Limit pro Session entfernt** — lang laufende Sessions lehnen keine neuen Agenten mehr ab (Concurrency- und Tiefenlimits gelten weiterhin)

**Änderungen:**
- Managed Settings: Genehmigungsprompt erscheint nicht mehr nach Re-Login oder Org-Wechsel, wenn die Org-Settings unverändert sind
- Feedback-Survey-Transcript-Share überträgt mit Zustimmung nun auch die letzten Modell-Einstellungen (System-Prompt inkl. `CLAUDE.md`, Tool-Definitionen, Parameter)
- Bash-Tool-Beschreibung weist jetzt darauf hin, dass Befehlsausgaben dem Modell, nicht zuverlässig dem Nutzer angezeigt werden
- Remote Control archiviert jetzt veraltete Server-Sessions statt sie als tote Einträge zu belassen

**VSCode-spezifisch:**
- Remote Control wurde nach fehlgeschlagener Verbindung als "connected" angezeigt — behoben
- Sessions honorierten `remoteControlAtStartup` nicht beim expliziten Aktivieren — behoben
- Session-Resume verbat sich beim stillen Reconnect von Remote Control nach Deaktivierung — behoben

### AWS AI Blog

**[Temporal Policies in Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/securing-ai-agents-with-temporal-policies-in-amazon-bedrock-agentcore/)**

Neue Kernfunktion für Agenten-Governance: Temporal Policies basieren auf **Dogwood** (neue Open-Source-Policy-Sprache, aufgebaut auf Cedar), die stateful Autorisierung für KI-Agenten ermöglicht. Statt jede Aktion isoliert zu prüfen, wird die gesamte Session-Trajektorie bewertet.

Konkrete Use Cases am Beispiel eines Banking-Agenten:
- **Workflow-Sequenzierung**: Pflicht-Reihenfolge von Tool-Calls (z.B. Profil abrufen → Portfolio laden → Trade ausführen)
- **Output-to-Input-Integrität**: Verhindert, dass Agenten zwischen Tool-Calls Werte halluzinieren oder substituieren
- **Datenfreshness**: Market-Preis muss innerhalb von 30s vor Trade abgerufen worden sein
- **Kumulatives Budget-Cap**: Max. $60.000 Trade-Volumen pro Session
- **Human-Approval**: Trades >$25.000 erfordern explizite Genehmigung, einmalig pro Trade verbrauchbar
- **Mutual Exclusion**: Kauf-Verkauf-Widersprüche innerhalb einer Session verhindern
- **Progressive Trust Decay**: Nach 15 Minuten ohne Advisor-Interaktion verliert Agent Write-Zugriff

Enforcement läuft am Gateway-Layer, außerhalb des Agenten-Codes — damit manipulationssicher.

**[Rate Limiting für AI-Traffic am AgentCore Gateway](https://aws.amazon.com/blogs/machine-learning/configure-rate-limits-for-ai-traffic-on-agentcore-gateway/)**

Neues Feature: Granulares Rate Limiting am AgentCore Gateway.

Unterstützte Metriken:
- **Request Rate Limits** (RPS/RPM): Für alle Target-Typen
- **Token Rate Limits** (TPM): Nur für Inference-Targets, zählt Input + Output Tokens
- **Connection Rate Limits** (CPS): Für alle Target-Typen, misst offene Verbindungen

Dimension Keys für differenziertes Rate Limiting:
- `targetName`, `toolName`, `qualifiedModelId` (Target-Ebene)
- `$.context.jwt.<claim>`, `$.context.iam.principal` (User-Ebene)

Mehrstufiges System: Gruppen-Limit + Benutzer-Limit kombinierbar, spezifischere Regeln gewinnen über Wildcards.

**[Enforcing Data Residency mit Claude Code auf Bedrock](https://aws.amazon.com/blogs/machine-learning/enforcing-data-residency-with-single-region-claude-code-on-amazon-bedrock/)**

Zwei Wege für Single-Region-Datenhaltung:

| | Path 1 (Mantle) | Path 2 (Classic Bedrock) |
|---|---|---|
| Regionen | 7 (u.a. Irland, Tokio, US) | 1 (London, eu-west-2) |
| Modelle | Sonnet 5, Opus 4.8, Haiku 4.5 | Opus 4.6, Sonnet 4.6 |

Für London (eu-west-2): Nur Path 2 verfügbar. IAM-Bedingung `aws:RequestedRegion` als Guardrail, CloudTrail-Verifizierung dokumentiert.

**[Agent Skills für Automated Reasoning in Bedrock](https://aws.amazon.com/blogs/machine-learning/agent-skills-for-automated-reasoning-policies-in-amazon-bedrock/)**
