### Anthropic & Claude

#### [Claude Code Releases — v2.1.252](https://github.com/anthropics/claude-code/releases/tag/v2.1.252)

Vier Bugfixes in diesem Release:

- **Bash-Absturz auf bestimmten Macs behoben** — Bash-Befehle schlugen fehl mit der Meldung "task output swap refused (tasks dir moved or linked)". Betroffen waren Macs, auf denen das Tasks-Verzeichnis verschoben oder verlinkt war.
- **"Always Allow" speichert nun korrekt** — In Projekten ohne vorhandene `.claude/settings.local.json`-Datei wurde die Einstellung nicht persistiert. Jetzt wird die Datei bei Bedarf angelegt.
- **Remote-Control-Sessions frieren nicht mehr ein** — Bei von Claude Desktop oder VS Code gehosteten Remote-Control-Sessions kam es bei schlechter Verbindung zu `claude.ai` zu minutenlangen Hängern nach Abschluss eines Tools.
- **Große Fehlerausgaben crashen Conversation nicht mehr** — Background-Task-Benachrichtigungen mit sehr großem Fehleroutput (z.B. Git-Fehler bei vollem Disk) konnten den API Request Size Limit überschreiten und die Konversation unbrauchbar machen.

### Big Labs — AWS

#### [AWS Agent Registry — Allgemein verfügbar](https://aws.amazon.com/blogs/machine-learning/manage-agents-tools-and-skills-at-scale-with-aws-agent-registry/)

AWS Agent Registry ist jetzt GA (General Available) und adressiert drei Kernprobleme beim Skalieren von KI-Agenten in Unternehmen:

**Was ist der Agent Registry?**
Ein zentraler, durchsuchbarer, governance-fähiger Katalog für Agenten, Tools, Skills und Custom Resources. Er besteht aus zwei Ebenen:
- **Governance Plane** — Vollständige Inventur aller Ressourcen, Compliance-Signale, Discovery-Policies, Custom Metadata Schemas
- **Discovery Plane** — Kuratierte, hochperformante Suche nur über genehmigte Ressourcen; unterstützt semantische und lexikalische Suche

**Unterstützte Record-Typen:** MCP-Server, A2A-Agenten, Skills, Custom-Ressourcen (JSON)

**Enterprise-Features:**
- Lifecycle-States: Draft → Pending Approval → Approved/Rejected → Deprecated
- EventBridge-Integration für Approval-Workflows
- Automatische Erkennung von Shadow-AI in der gesamten AWS-Organisation
- CI/CD-Pipeline-Integration für Publisher
- Discovery aus IDEs (inkl. Claude Code) via MCP-Server-Interface
- Discovery aus Amazon Quick für Business-User
- Pricing: Consumption-based mit AWS Free Tier
- Verfügbar in: US East, US West, EU (Ireland), AP (Tokyo, Sydney)

**Kundenaussagen:** Southwest Airlines, PepsiCo, Syngenta, Amdocs — alle berichten von eliminierten Duplikaten und zentralisierter Governance.

#### [AWS — MCP-Server in AgentCore Runtime → Amazon Quick](https://aws.amazon.com/blogs/machine-learning/connect-an-agentcore-runtime-hosted-mcp-server-to-amazon-quick/)

Schritt-für-Schritt-Guide zur Integration eines MCP-Servers auf AgentCore Runtime mit Amazon Quick:

1. MCP-Server mit `FastMCP` (stateless_http=True) implementieren
2. Via `agentcore configure` + `agentcore launch` in AgentCore Runtime deployen
3. AgentCore Gateway mit Inbound Auth (Amazon Cognito) und Outbound Auth (AgentCore Identity / OAuth 2.0) konfigurieren
4. In Amazon Quick als MCP-Connector registrieren und in Chat-Agent einbinden

Das Pattern fördert Tool-Wiederverwendung: Kunden können MCP-Tools in Amazon Quick-Workflows nutzen ohne Custom Connectors zu bauen.

#### [AWS — Beobachtbares Agentic Retrieval mit Managed Knowledge Base](https://aws.amazon.com/blogs/machine-learning/build-observable-enterprise-agentic-retrieval-using-managed-amazon-bedrock-knowledge-base-with-aws-cloudformation/)

Vollständige Enterprise-Lösung für Multi-KB-Routing-Agent mit 7 Observability-Layern, deployt via single CloudFormation-Chain:

**Architektur:** AgentCore Runtime (OpenTelemetry auto-instrumented) → AgentCore Gateway (MCP) → Managed Knowledge Base (AgenticRetrieveStream)

**7 Observability-Layer:**
1. KB-native Metriken (Retrieve-Aufrufe, Fehler, Throttles)
2. Ingestion-Status pro Dokument
3. Retrieval-Qualität (referenzfrei: Utilization, Coverage, Duplicate Rate)
4. Gateway/MCP-Metriken und Latenz
5. OTEL Span-Tree (vollständiger Reason-and-Act-Trace)
6. Token-Nutzung pro Session/Modell
7. Evaluations-Scores (Correctness, Faithfulness, Tool-Selection, Response Relevance)

**Evaluierung:** On-demand (Notebook) + Continuous/Online (automatisches Sampling aus Live-Traffic). Warnung: `SamplingPercentage: 100` nur für Demo — in Produktion anpassen!

**Deployment:** `./scripts/deploy.sh us-west-2 bmkb-ml21427` — 4 CloudFormation-Stacks, ca. 8–10 Minuten.

#### [AWS — Multi-Tenant Agentic Chat mit Managed Knowledge Base](https://aws.amazon.com/blogs/machine-learning/build-multi-tenant-agentic-chat-applications-on-enterprise-data-with-amazon-bedrock-managed-knowledge-base/)

Architektur für mandantenfähige Dokumenten-Chat-Applikation:

**Kernkomponenten:** Managed KB (kein Vektorspeicher nötig), API Gateway + Lambda, Amazon Cognito (Identitätsisolation), SQS (Entkopplung Upload/Ingestion), DynamoDB (Indexierungsstatus)

**Isolation-Mechanismus:** Jedes Dokument wird mit `user_id` (aus verifiziertem JWT) getaggt. Jede `AgenticRetrieveStream`-Abfrage filtert serverseitig auf diese `user_id` — niemals clientseitig.

**Indexierungs-Lifecycle:** STARTING → PENDING → IN_PROGRESS → TEXT_INDEXED → INDEXED. Empfehlung: Dokument bei `TEXT_INDEXED` als suchbar markieren (nicht erst bei `INDEXED`).

**Timings (Richtwerte bei kleinen Dokumenten):** Plaintext: 2–3 Sekunden; PDF: ~5–30 Sek. für TEXT_INDEXED, ~90 Sek. für vollständiges INDEXED.

**Best Practices:** SQS für Burst-Handling, bis zu 10 Dokumente pro API-Call batchen, Concurrency-Limit als retryable `ValidationException` behandeln, Conversation History selbst persistieren.
