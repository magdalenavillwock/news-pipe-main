### VentureBeat

**[DeepSeek senkt Preise 75% — das 100x-Problem bleibt](https://venturebeat.com/orchestration/deepseek-cut-prices-75-the-100x-problem-remains)**

Ein tiefgehender Analyse-Artikel von zwei ML-Engineers, der die strukturelle Kostenproblematik agentic KI-Systeme aufzeigt:

**Das Kernproblem — Token-Amplifikation:**
- Ein Chatbot: 1 Nutzeranfrage → ~1 Modellaufruf (Input/Output-Ratio ~1:5)
- Ein Agent: 1 Nutzeranfrage → Planung, Retrieval, Tool-Aufrufe, Verifikation, Summarisierung → Input/Output-Ratio **1:700 oder höher**

**Konkretes Beispiel** ("Was hat unser Top-Kunde letzte Woche gefragt?"):
1. User Prompt: ~50 Tokens
2. System Prompt + Tool-Definitionen: ~3.000 Tokens (bei **jedem** Call wiederholt)
3. Retrieval-Kontext: ~5.000 Tokens
4. Modellaufruf #1 (Tool-Auswahl): 8.000 in / 200 out
5. Tool-Execution: ~4.000 Tokens
6. Modellaufruf #2 (Summarisierung): 12.000 in / 400 out
7. Modellaufruf #3 (Follow-up): 12.400 in / 100 out

**Ergebnis:** ~35.000 Input-Tokens für eine Nutzeranfrage → $0,10–0,40 pro Query auf Frontier-Modellen. Bei 1 Mio. Queries/Monat: sechsstelliger Kostenpunkt.

**Warum das SaaS-Modell bricht:**
- Klassische Seat-basierte Preisgestaltung ($40/User/Monat) setzt begrenzte Kosten pro User voraus
- Heavy-User mit 50–100 Agent-Anfragen/Tag können mehr in Inference kosten als ihr Monatsabo einbringt
- Mehrere Anbieter berichten intern von **negativen Bruttomargen** bei Heavy-Usern
- Salesforce Agentforce: Kluft zwischen Marketing-Demos und tatsächlich ausgelieferten Features

**Technische Gegenmaßnahmen:**
- **Cost-aware Routing**: Kleines Classifier-Modell wählt Modell-Tier → ~60% Kostensenkung ohne Qualitätsverlust
- **Prompt Caching**: Anthropic, OpenAI, Google bieten 75–90% Rabatt auf gecachte Prefixe
- **Context Discipline**: Tool-Outputs kürzen, Reasoning Traces prunen, Tool-Tiefe deckeln
- **Speculative Decoding**: 2–3x Durchsatz auf gleicher GPU-Hardware (Self-Hosted)

**Strategische Empfehlungen für Unternehmen:**
1. Inference-Kosten als First-Class-Metrik tracken (pro Feature, pro Tenant, pro Query-Klasse)
2. Cost-per-1000-Queries-Obergrenzen pro Feature definieren
3. Den Router als Core-Infrastruktur behandeln (nicht als Optimierung)
4. System-Prompts quartalsweise auditieren (gewachsene 4.000-Token-Prompts = sechsstellige Rechnung)
5. Volume-Commits frühzeitig verhandeln — List Price ist immer der schlechteste Preis
